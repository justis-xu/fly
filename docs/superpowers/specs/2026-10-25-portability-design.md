# fly 可迁移性与可用性检查设计

用户已授权：整体检查，直接修复，验收后全部提交推送。沿用一个蓝白管理页、Go 单程序、默认 7888 代理 / 7889 管理、Proxy Switcher 浏览器接入。不增加系统代理、TUN、控制端口或常驻 Node 服务。

## 验收目标

1. 新电脑、新用户目录、没有 Clash / 环境代理、没有旧缓存时，能按手册安装、启动、添加自己的订阅并访问测试服务。提供 FLY_HOME 作为独立数据目录入口以实测隔离环境；默认仍 ~/.fly。
2. 订阅下载明确直连，不能暗中依赖 HTTP_PROXY / HTTPS_PROXY。直连失败可使用用户明确设置的 HTTP / SOCKS5 下载代理，或现有 fly 的所选节点；首次无可用出口时可以导入已下载的订阅文件。错误说明超时、认证、网页而非订阅、超限和不支持格式；不泄漏 URL 凭据。
3. URL 与文件输入均先校验有效节点与规则，再激活和保存；失败保留旧运行配置和旧地址。按来源隔离缓存，绝不把上一份订阅冒充新订阅。成功更新和规则编辑才替换有效状态；磁盘写入失败明确报告。
4. 支持 Clash proxies YAML、明文 / base64 节点链接和常见 HTTP/inline proxy-providers。过滤失效 / 不支持节点并说明跳过数量，避免保留名 / 重名覆盖；不静默忽略分享链接的关键协议参数。订阅自带的监听、控制和系统配置不能开启额外服务。
5. 规则单独弹窗：搜索订阅分流项、查看规则集内容 / 加载状态；用户可添加、修改、排序和删除域名或 IP 网段的代理 / 直连 / 拒绝规则。用户规则先匹配，独立保存，更新订阅后保留；无效编辑不破坏现状。域名测试可解释命中的用户规则，复杂订阅规则以实际访问测试为准。
6. 节点支持订阅顺序、名称、延迟、可用优先排序，自动选择固定置顶，失败和未测状态不能当作 0 ms。可搜索筛选，不改变用户选中的节点。
7. 延迟测试与网站测试是两项操作。延迟明确目标、GET/HEAD 方法、超时、并发和时间，异步进度、取消、未开始和失败有区分。网站测试固定所选实际节点（自动策略解析一次），独立请求常用网站，显示 HTTP 状态 / 访问受限 / 连接失败；不切换节点，不等同账号登录、区域解锁或全站保证。还可通过本机 mixed 代理核对实际分流路径。
8. 本机监听、订阅就绪、节点健康、网站结果分开显示，不能用“服务运行中”保证互联网可用。手动节点故障给出换节点 / 自动选择入口；检测可用性需明确用户触发，自动健康检查解释清楚。
9. UI 保持一个主页面，细节放弹窗 / 折叠区。更新所有用户文档和无凭据截图；排查覆盖首次下载打不开、缓存、订阅变更、节点突然失效、规则资源失败、403 / 429 与真正断网区别。

## 验证证据

- Go / React 故障回归，先观察失败再实现；真实 HTTP 服务模拟代理环境、失效订阅、两份不同订阅、错误规则、取消测试、受限网站。
- 独立 HOME / FLY_HOME，清空代理环境的新进程；启动、导入、切订阅、离线重启、规则持久化、HTTP/SOCKS 转发和停止，独立临时端口与资源全部清理。
- 浏览器检查桌面 / 窄屏、排序、规则编辑、测试进度和错误提示；真实账户只做必要本机验证，不进入截图和提交。
- 独立最终审查、完整测试 / 构建、生成网页一致性验证、敏感链接扫描、GitHub CI、提交推送后工作区与远端一致。

不承诺所有服务商格式、节点、网站永远可用；受支持输入、具体失败原因和恢复途径必须可验证。不能以缩减上述功能或跳过失败检查代替完成。
