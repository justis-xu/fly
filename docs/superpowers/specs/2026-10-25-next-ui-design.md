# fly Next.js 管理界面设计

用户已批准直接执行：Next.js + React + TypeScript + shadcn/ui，保持蓝白风格和单页面，图文手册面向首次使用者，检查后全部提交推送。

## 运行方式

浏览器 → Proxy Switcher → 本机 fly HTTP / SOCKS5 7888 → 用户订阅节点或按规则直连。管理网页仍为 7889。Go API、mihomo、订阅规则、缓存和 CLI 生命周期沿用现有实现。

Next.js App Router 使用静态导出，前端文件嵌入 Go 二进制。无 Next.js 生产服务器，无新增运行端口。Node.js 仅参与前端开发/构建。提交源码、锁文件及内嵌静态产物，普通安装可直接使用仓库内已构建网页；开发者执行统一前端构建命令刷新产物。

## 页面

页头显示 fly、本机服务状态和使用帮助。首次使用以三步提示：添加订阅、配置 Proxy Switcher、选择节点。主卡片显示当前节点与插件应填写的地址。节点列表支持搜索、自动选择、测速；侧边订阅卡片展示流量、到期、更新时间及修改入口。规则详情折叠显示。加载、断连、后台刷新、缓存回退和规则未就绪均须明确呈现，操作失败不得被轮询立刻抹去。

保留蓝白底色、清晰留白和响应式布局。仅采用所需组件：Button、Card、Input、Badge、Dialog、Alert、Accordion。字体采用系统字体，无运行时外部字体依赖。订阅地址输入默认遮蔽，禁止在截图、日志及生成的网页中嵌入真实订阅。
