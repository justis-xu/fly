# 订阅地址、文件和下载要求

这页先回答「什么能填进 fly」，再说明失败时怎么处理。具体按钮和截图见[日常使用手册](USAGE.md#3-第一次添加在线订阅)。fly 和 Proxy Switcher 都不附带套餐、节点或免费出口，需要你自己的订阅。

## 1. 先从服务商复制正确内容

1. 登录你自己的服务商账号。
2. 找「订阅」「导出」「客户端」之类的入口。
3. 优先选择 **Clash / Mihomo / Clash Meta** 格式。
4. 点「复制订阅链接」，复制完整的 `http://` 或 `https://` 地址，包括问号后的令牌 / 参数。
5. 不要复制网站登录页、付款页、账号首页、PAC 文件地址或网页上的节点显示名称。
6. 链接在浏览器显示 YAML / 下载配置文件，通常是好迹象；出现登录页、验证码、报错 HTML，不能当作订阅。浏览器能打开也不保证服务端用同样网络能下载。

订阅链接相当于凭据，不要发进公开 issue、聊天截图或仓库。本文的 `example.org` 只用于解释，不能作为真实订阅使用。

## 2. 支持什么格式

| 输入 | 支持情况 / 条件 |
|---|---|
| Clash/Mihomo YAML，含 `proxies` | 推荐；节点仍要符合内嵌内核支持的协议和参数 |
| 每行一条节点分享链接 | 支持 SS、VLESS、VMess、Trojan、Hysteria2 / hy2 的已实现常见参数 |
| 上述链接列表的 base64 | 支持 |
| `proxy-providers` 的 HTTP 或 inline 节点来源 | 支持常见来源；HTTP 来源须返回含 `proxies` 的 Clash YAML；会合并节点后缓存 |
| HTTP 节点来源的 filter / exclude-filter | 支持 Go 正则；常见名称前后缀和少量基础 override 支持；其他 override 明确报错 |
| HTTP 节点 / 规则来源的认证请求头 | 支持标准文本请求头，例如 Authorization、User-Agent；跨域重定向不转发认证等私有自定义头 |
| Clash 规则、HTTP / inline 规则集、子规则 | 支持有效的常见结构；规则集可使用 YAML、text、domain/ipcidr MRS |
| Xray / sing-box 完整 JSON、PAC、登录网页 | 不能直接导入；请让服务商导出 Clash/Mihomo |
| 引用本机路径的 file 节点来源 / 规则集 | 不读取；请先导出已合并内容，避免依赖另一台电脑上的路径 |
| 递归的远端节点来源 | 不支持；请导出已展开的 Clash YAML |
| SS 分享链接里的 plugin、未实现的传输 / 伪装参数 | 不会假装支持；该链接会跳过，请改用服务商的完整 Clash YAML |

不是所有服务商导出都能无损转换成这个简化服务器。协议的具体有效性会交给 mihomo 适配器检查；部分无效节点会跳过，页面显示跳过数量。节点全部无效则报错，不会用一份空配置替换当前配置。

重名会自动区分；与内核保留名冲突的节点会改名。没有名称的常见分享链接会用类型与服务器生成名称。占位信息按明确的常见提示前缀过滤，不因正常名字中出现「官网」「到期」就删掉节点。

## 3. 大小和内容限制

- 单个订阅 / 节点来源响应或导入文件最多 **8 MiB**；超过会明确拒绝，不会截断后继续解析。
- 合并后最多 **2000 个节点**、最多 **32 个远端 / 内联节点来源**，不支持来源递归。
- 自定义用户规则最多 **200 条**。规则集查看每页最多 100 条，可搜索和翻页。
- 导入文件使用文本内容，推荐 UTF-8。普通压缩包、图片、浏览器下载的登录 HTML 不是订阅。
- 名字、UUID、加密方式、端口等必须有效；端口范围 1–65535。某个协议不能解析时，优先换 Clash/Mihomo 导出，不要随机改凭据或关闭证书验证。

fly 只采用节点和分流相关内容。订阅里的系统代理、TUN、额外监听端口、独立控制页面、DNS 监听等不会开启。代理分组收敛为当前所选节点 / 自动选择；明确的直连、拒绝等策略保留。

## 4. 下载走哪条路

1. 明确直连。
2. 连接失败 / 访问受限时，尝试你在弹窗明确设置的备用 HTTP(S) / SOCKS5 下载代理。
3. 仍失败且 fly 已有节点时，尝试开始下载时固定的当前实际节点，避免依赖订阅自己的分流规则。

不会隐式读取环境代理。下载有总时限和单次超时；保存期间请等待页面结果。401 / 404 这类账号 / 地址问题不靠反复换出口重试解决。

备用代理必须已在运行；仅填一个端口不会凭空创建代理。首次没有任何出口时，可在能下载订阅的环境导出文件，再导入这台电脑。文件里的远端来源 / 规则资源仍需首次联网取得；需要离线使用时，请让服务商导出已展开节点及内联规则的完整文件。

## 5. 常见失败与处理

| 提示 / 现象 | 优先处理 |
|---|---|
| 地址需要 http(s) | 重新复制完整链接，不填账号首页、节点名或缺少协议的地址 |
| HTTP 401 | 账号凭据可能无效，检查套餐或让服务商重新给链接 |
| HTTP 403 | 可能是源站访问限制；核对服务商要求，再考虑备用下载出口 |
| HTTP 404 | 地址不存在或复制不完整，重新复制 |
| HTTP 429 | 请求太频繁，稍后再试，避免连续点更新 |
| DNS 解析失败 | 核对域名，检查本机网络 / DNS；能取得文件时可以导入 |
| 连接失败 / 超时 | 检查网络、源站与备用代理是否实际可用 |
| 证书无法验证 | 检查系统时间、证书环境和服务商；不要随意关验证 |
| 收到网页而非订阅 | 复制了登录页 / 网关页，改用 Clash/Mihomo 订阅入口 |
| 没有有效节点 | 核对导出格式、协议、凭据和端口；查看跳过数量 |
| 节点来源下载失败 | 主文件可能可达，但它引用的来源不可达；核对相应来源或导出展开版 |
| 规则集首次下载失败 | 不能完整启用新配置；设置有效下载出口，或使用内联规则导出 |
| 规则资源更新失败，保留缓存 | 当前使用的是之前的规则资源，恢复网络后再更新 |
| 保存失败 / 空间或权限问题 | 检查磁盘空间和自己的数据目录权限；不要用 sudo 反复启动来绕过问题 |

## 6. 缓存究竟能保证什么

- 每个来源按地址指纹单独保存最后可用内容；更换地址时不把旧来源当成新来源。
- 新内容先验证和启用，缓存写好后才持久化新地址；磁盘写入失败会报告，并恢复旧运行配置。
- 在线下载失败但程序已经在运行时保留当前配置；重启时只读取当前来源对应的缓存。
- 规则缓存也与其来源绑定。下载失败可以保留已有可用资源，但会提示本次没更新成功。
- 缓存里节点仍可能过期 / 下线。缓存能恢复配置，不承诺出口一定连通；还要测网站。
- 从早期版本升级时，旧缓存没有来源记录。为保留原有离线能力，只对既有地址尝试一次迁移，并明确标成「旧缓存（来源未核实）」；联网成功更新后才消除这个提示。新地址验证失败不会借用它。

默认私有数据在 `~/.fly/`：`fly.yaml` 是设置，`rules.yaml` 是用户规则，`subscriptions/` 是按来源保存的订阅缓存，`rules/` 是规则资源，另有内核选择缓存和日志。目录和凭据文件不应上传到 GitHub；卸载程序不会主动删除这些数据。
